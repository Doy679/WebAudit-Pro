# WebAudit Pro

Read-only website UX/UI audits with evidence, internal review, Excel/PDF reports, client approval and re-audit comparison.

- Status of the 8 MVP milestones: [`WEBAUDIT_MVP_CHECKLIST.md`](WEBAUDIT_MVP_CHECKLIST.md)
- Design: [`docs/design/2026-11-03-webaudit-pro-app.md`](docs/design/2026-11-03-webaudit-pro-app.md) (app), [`docs/design/2026-10-29-webaudit-pro-poc.md`](docs/design/2026-10-29-webaudit-pro-poc.md) (engine)
- Rule accuracy work on the CHM pilot: [`docs/rule-accuracy.md`](docs/rule-accuracy.md)

## Requirements
- Node.js 22+ (developed on 26). On this PC, Node is a portable install in `%LOCALAPPDATA%\Programs\nodejs-portable` and is on the user PATH.
- Microsoft Edge (used by Playwright for scanning and PDFs). Set `WEBAUDIT_BROWSER_CHANNEL=chrome` for Chrome, or empty plus `npx playwright install chromium` for the bundled browser.

## Start the app

```sh
npm install
npm run setup        # once: creates .env.local (server secret) and data/
npm run dev          # web app + background worker
```

Open **http://localhost:3000**. On first run you are sent to `/setup` to create the admin account. Alternatively:

```sh
npm run create-admin -- --email you@agency.com --name "Your Name" --password "at least 10 characters"
```

Production-style run: `npm run build` then `npm start` (also starts the worker).

## Typical workflow
1. **My Websites → Add website**: name, address, and the authorization you hold (recorded with your name and time).
2. **New Audit**: confirm the URL, choose pages, viewports, categories and scan rate, then **Start Audit**.
3. Watch progress on the audit page (safe to refresh, and you can cancel).
4. **Issues**: filter, open a finding, check the screenshot and Current vs Proposed, then confirm or mark it a false positive, approve or reject, assign, set priority, add notes.
5. **Reports**: generate Excel (developers) or PDF (clients), plus HTML/JSON.
6. **Client Approvals**: release reviewed findings and copy the private link (shown once). The client decides on the link page.
7. After fixes are deployed separately, **Re-Audit**: run a fresh scan and compare.

## Configuration (`.env.local`)
| Variable | Purpose |
|---|---|
| `WEBAUDIT_SECRET` | Encrypts stored secrets (AI key). Generated by `npm run setup`. |
| `WEBAUDIT_DATA_DIR` | Database, screenshots, reports (default `data/`, never served publicly). |
| `WEBAUDIT_APP_URL` | Base URL for links in reports. Use `https://…` in deployment; this also turns on Secure cookies. |
| `WEBAUDIT_BROWSER_CHANNEL` | `msedge` (default), `chrome`, or empty for bundled Chromium. |
| `WEBAUDIT_MAX_STORAGE_GB` | New audits refuse to start above this data size (default 20). |
| `WEBAUDIT_TEST_ALLOW_LOOPBACK` | **Tests only.** Allows auditing 127.0.0.1 fixture sites. Never set it in production. |

Engine thresholds and the default crawl politeness live in `config/tokens.json`. Per-project design standards override them.

## Command line (engine only)
```sh
npm run audit -- --url https://example.com --max-pages 20
npm run demo                                 # audits the built-in fixture site
npm run recheck -- runs/<domain>/<timestamp> # re-run current rules on a saved run's snapshots
```

## Tests
```sh
npm test            # unit + integration (real browser against a local fixture site)
npm run test:e2e    # builds the app, then drives it end to end (14 scenarios)
npm run typecheck
```
`E2E_SCREENSHOTS=1 npm run test:e2e` also saves desktop and phone screenshots of key screens to `test-results/`.

## Safety rules built in
- Read-only: the browser aborts every non-GET/HEAD request. No clicks, form fills, logins or publishing.
- Scope: audits only run on the project's domain, after an authorization is recorded. robots.txt is respected, one page loads at a time, with a delay of at least 500 ms.
- SSRF: private, loopback, link-local, metadata and reserved addresses are blocked for every request and redirect hop.
- Evidence and reports are only served to signed-in project members. Client links are hashed, expiring and revocable, and expose only the released findings.
- Approving a finding (internally or by the client) changes review records only.

## Known limitations
See the per-milestone limitations in the checklist. In short: SQLite only, public pages only, no email sending, in-memory rate limits, and AI explanations not yet tested against the live API. This is a local MVP and is **not production-ready** without deployment hardening (HTTPS, backups, process supervision, a security review).
